Alcance: registro de fuentes, ingesta, calidad, almacenamiento, API, CLI, modelos dbt, Docker, pruebas y YAML de fuentes.

2 · Hallazgo principal

Cómo se perdían datos con max_records

La fecha de publicación de SECOP solo distingue días (2026-01-08T00:00:00.000) y hay entre 5 000 y 27 000 procesos por día. El tope de 50 000 registros por ejecución cortaba la carga a mitad de un día. El cursor saltaba a ese día, y la siguiente carga pedía fecha > '2026-01-08': el resto de ese día no volvía a pedirse nunca.

En la capa de origen el 8 de enero suma 20 119 filas: 3 669 de la primera carga y 16 450 de la segunda. Las repetidas se resuelven en la capa estandarizada por la llave id_del_proceso.

3 · Correcciones

Fallos encontrados y corregidos

Crítico

Pérdida de datos con max_records

Corregido
Dónde
src/plataforma/ingestion/engine.py
Qué pasaba
Al cortar la carga a mitad de un día, el cursor avanzaba a ese día y el resto de sus filas quedaba excluido por el filtro estricto >.
Corrección
Nueva función next_cursor(): si el tope cortó la carga, el cursor se queda en el valor anterior y ese grupo se vuelve a pedir completo.
Verificado
Con datos reales (ver sección 2) y con una prueba unitaria nueva.
Alto

Paginación sin orden estable

Corregido
Dónde
sources/secop_procesos.yml
Qué pasaba
Se ordenaba solo por fecha y miles de filas comparten la misma. Con paginación por offset, Socrata puede saltar o repetir filas entre páginas.
Corrección
$order: fecha_de_publicacion_del ASC, :id ASC. Se comprobó que la API lo acepta.
Alto

Secretos guardados en claro en el catálogo

Corregido
Dónde
src/plataforma/storage/catalog.py
Qué pasaba
Solo se ocultaba el bloque auth. Un headers: {Authorization: …} o un params: {api_key: …} quedaba visible en meta.sources y en GET /sources/{name}.
Corrección
También se ocultan las claves de headers y params cuyo nombre parece una credencial (auth, token, key, secret, password…).
Medio

plataforma validate se caía en Windows

Corregido
Dónde
src/plataforma/cli.py
Qué pasaba
Con la salida redirigida (archivo, tubería, tarea programada o CI) fallaba con UnicodeEncodeError por el carácter ✓.
Corrección
El carácter se reemplaza en vez de romper el comando. Se agregó el alias -n en inspect; antes solo existía --n.

Fallos menores en la ingesta REST

Corregido
Dónde
src/plataforma/ingestion/rest.py
Autenticación
Con un cliente HTTP inyectado, las cabeceras de autenticación no se enviaban. Ahora van en cada petición.
Retry-After
Si el servidor enviaba la espera como fecha HTTP en vez de segundos, se lanzaba ValueError. Ahora acepta ambos formatos.
Medio

Otros problemas

Corregido
  • Ejecuciones colgadas. Si fallaba la creación de la tabla de origen, la ejecución quedaba en running para siempre. Esa creación ahora está dentro del try.
  • Cursores nulos. Los registros sin valor de cursor se volvían a cargar en cada ejecución. Ahora se tratan como en SQL: nunca cuentan como posteriores.
  • dbt beta. pip instalaba dbt-core 1.13.0b1. Se limitó a versiones estables en pyproject.toml y ahora usa la 1.12.6.
  • Imágenes duplicadas. Docker construía tres imágenes idénticas de 1,2 GB. Ahora docker-compose.yml usa una sola: plataforma-datos:local.
4 · Pendientes

Observaciones que requieren una decisión

  1. id_del_proceso no es único.El 2 de enero hay 5 506 filas y solo 5 253 ids distintos: el dataset tiene una fila por proceso × proveedor adjudicado. La capa estandarizada se queda con una fila arbitraria por proceso. Sirve para precio_base, pero pierde los datos de adjudicación; si se necesitan, hace falta un modelo aparte.
  2. No se capturan actualizaciones.El cursor usa la fecha de publicación, así que los cambios de fase o adjudicación de procesos ya cargados no llegan. Para eso habría que usar fecha_de_ultima_publicaci.
  3. Ritmo de carga.Hay 1,56 millones de registros desde 2026. A 50 000 por ejecución, ponerse al día toma unas 31 ejecuciones de unos 4 minutos cada una.
  4. Linter.Quedan 19 avisos de estilo de ruff que ya existían. B008 es un falso positivo típico de FastAPI.
  5. Makefile.Usa sintaxis de shell POSIX. En Windows funciona con Git Bash, no con cmd.
